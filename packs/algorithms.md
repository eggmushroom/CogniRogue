## 复杂度

### 二分查找在 n 个有序元素上的最坏时间复杂度是？
@ 二分查找的代价
A) O(1)
B) O(log n)
C) O(n)
D) O(n log n)
= B
+ 每次比较把搜索区间折半，最多比较约 log2(n) 次。前提是数组「有序」，无序数组先排序就已经是 O(n log n) 了。
% 6 5 pierce

? 理解: 为什么无序数组上不能直接用二分查找？
A) 无序数组不具备"折半后目标仍在某一侧"的性质
B) 无序数组算不出中间下标
C) 无序数组按下标访问是 O(n)
D) 无序数组元素太多，递归会爆栈
= A
+ 二分的关键不是"有序"，而是"有序"带来的可判定性：比过 mid 之后，你能确定目标只可能在左半边或右半边。无序时这个断言失效，折半就变成了瞎猜。

? 迁移: n = 1024 的有序数组，二分查找最多比较几次？
A) 10
B) 32
C) 512
D) 1024
= A
+ 2 的 10 次方是 1024，区间从 1024 缩到 1 需要 10 次折半。记住这个换算比记公式有用。

### 递归式 T(n) = 2T(n/2) + O(n) 的解是？
@ 主定理：平衡划分
A) O(n)
B) O(log n)
C) O(n log n)
D) O(n²)
= C
+ 这正是归并排序的结构：分成两个 n/2 的子问题，再花 O(n) 合并。按主定理属于「平衡划分、线性合并」，结果是 O(n log n)。
% 7 5 chain

? 理解: 这个递归式里的 2 和 n/2 分别对应什么？
A) 两个规模减半的子问题
B) 两次比较，每次跳过一半
C) 两层嵌套循环，每层 n/2
D) 两个长度为 n/2 的辅助数组
= A
+ 系数 2 是子问题个数，n/2 是每个子问题的规模。递归树每一层的总代价都是 O(n)，树高是 log n，乘起来才是 O(n log n)。

? 迁移: 如果合并步骤从 O(n) 变成 O(n log n)，总复杂度是多少？
A) O(n log² n)
B) O(n log n)
C) O(n²)
D) O(n√n)
= A
+ 每层代价升到 O(n log n)，层数仍是 log n，相乘即 O(n log² n)。这是"多一层对数因子"，不是平方。

### 快速排序的最坏时间复杂度出现在什么情况下？
@ 快排的坏运气
A) 数组已经完全有序，且取首元素为枢轴
B) 数组随机排列
C) 数组元素全部相等
D) 元素数量是 2 的幂
= A
+ 已排序 + 首元素枢轴，每次划分都极不均衡（一侧空、一侧 n-1），退化成 O(n²)。三数取中或随机化枢轴就是为了打散这种最坏情况。
% 8 5 strike

? 理解: 快排退化成 O(n²) 的根本原因是？
A) 每次划分极不均衡，递归树退化成一条链
B) 元素个数太多
C) 递归层数太浅
D) 每次比较的开销太大
= A
+ 快排的代价是「每层 O(n) × 层数」。均分时层数是 log n；每次只剥掉一个元素时层数是 n，于是 O(n²)。所以问题永远出在划分的均衡性上。

? 迁移: 每次都用三数取中选枢轴，能不能保证最坏 O(n log n)？
A) 不能，仍然存在被构造出来的最坏输入
B) 能，三数取中必然均分
C) 能，因为它等价于随机化枢轴
D) 不能，因为枢轴取值不唯一
= A
+ 三数取中只是降低了碰到坏输入的概率，没有消除它。要拿到最坏情况的线性保证，得用 median-of-medians 这类确定性选择算法，代价是常数极大。

### 哈希表里所有键都冲突、全部挤在同一条链上时，查找的复杂度是？
@ 哈希退化
A) O(1)
B) O(log n)
C) O(n)
D) O(n log n)
= C
+ 冲突全部堆在一起时，哈希表在结构上退化成了链表，查找变成线性扫描。所以 O(1) 是平均情况，不是最坏情况。
% 7 5 guard

? 理解: 为什么哈希表的 O(1) 是平均情况而不是最坏情况？
A) 冲突会让链变长，最坏时退化成线性扫描
B) 哈希函数本身的计算是 O(n)
C) 扩容时需要重新插入所有元素
D) 哈希表不支持删除操作
= A
+ 均摊 O(1) 的前提是「冲突足够均匀」。一旦哈希函数把键集中到少数桶里，桶内查找就回到了线性结构的老路。

? 迁移: 开放寻址法、装载因子已经到 0.9 时，查找性能会怎样？
A) 明显变慢，探测链变长且缓存失效
B) 不受影响，仍是 O(1)
C) 反而变快，内存更紧凑
D) 变成 O(1) 的最坏情况
= A
+ 开放寻址的成功查找期望探测次数约 1/(1-α)，α 从 0.5 涨到 0.9 时从 2 次涨到 10 次。这就是为什么实现普遍在 0.7 左右就扩容。

## 数据结构

### 同时需要「尾部插入均摊 O(1)」和「随机访问 O(1)」，应该选什么？
@ 动态数组的取舍
A) 单链表
B) 动态数组（可扩容数组）
C) 二叉搜索树
D) 哈希表
= B
+ 数组的连续内存天然支持下标随机访问；尾部追加均摊 O(1)（扩容那一次是 O(n)，摊还后可以忽略）。链表随机访问是 O(n)，哈希表不支持按下标访问。
% 6 5 focus

? 理解: 为什么扩容要按倍数（比如 2 倍）而不是每次加 1？
A) 均摊之后每次追加才是 O(1)
B) 倍数扩容更省内存
C) 为了支持按下标随机访问
D) 语言运行时规定必须这样
= A
+ 每次 +1 的话，n 次追加累计复制 n²/2 个元素；每次翻倍则是 1+2+4+…+n < 2n。均摊分析里，这个"翻倍"就是 O(1) 的全部来源。

? 迁移: 从空数组开始连续 push n 次，累计复制的元素数量级是多少？
A) O(n)
B) O(n log n)
C) O(n²)
D) O(1)
= A
+ 等比数列求和上限是 2n。注意区分「单次最坏 O(n)」和「n 次总计 O(n)」——均摊就是拿这两个数相除。

### 优先队列（每次取出最小元素）最常用的底层实现是？
@ 堆的用途
A) 有序数组
B) 二叉堆
C) 哈希表
D) 平衡树
= B
+ 二叉堆插入和删除堆顶都是 O(log n)，查看堆顶 O(1)，常数小、实现简单。有序数组插入是 O(n)，每次插都要挪元素。
% 7 5 strike

? 理解: 二叉堆查堆顶是 O(1)，插入却是 O(log n)，原因是？
A) 堆顶固定在数组第 0 位，插入要沿树上升
B) 堆顶需要实时排序，插入直接放尾部
C) 两者其实都是 O(1)
D) 因为堆是链式结构，指针跳转慢
= A
+ 堆只保证「父子有序」这一条弱不变量，所以最小值天然在根上。插入时破坏的是从叶到根这条路径，恢复它恰好要走 log n 步。

### 并查集同时使用「路径压缩」和「按秩合并」后，单次操作的均摊复杂度约是？
@ 并查集的两把刷子
A) O(1)
B) O(log n)
C) O(n)
D) O(n α(n))
= A
+ 两者结合后均摊代价是 O(α(n))，α 是阿克曼函数的反函数，在实际规模下不超过 4，因此工程上直接当作 O(1)。
% 8 6 chain

? 理解: 只做路径压缩、不做按秩合并，复杂度会变成什么样？
A) 仍然很快，但理论界退化到 O(log n) 均摊
B) 直接退化到 O(n)
C) 完全不变，两种优化等价
D) 变成 O(n log n)
= A
+ 两个优化各自能拿到 O(log n)，合起来才能拿到接近常数的 α(n)。工程上两个都写几乎不增加成本，没有理由只写一半。

? 迁移: 并查集不擅长支持下面哪个操作？
A) 从一个集合中删除单个元素，并恢复它原来的归属
B) 查询两个元素是否属于同一集合
C) 合并两个集合
D) 查询某个集合的大小
= A
+ 并查集只支持「合并」，不支持「拆分」或「删除」。这是它的结构性局限，也是为什么带删除的动态连通性要用别的方法（如 LCT 或离线倒序处理）。

### 布隆过滤器判断一个元素「不存在」时，结论的正确性如何？
@ 布隆的假阴性
A) 一定正确
B) 可能误判为存在
C) 可能误判为不存在
D) 完全随机
= A
+ 布隆过滤器只有假阳性（说不存在就一定不存在）、没有假阴性。所以它适合「挡掉一定不存在」的请求，不能当作「一定存在」的证明。
% 8 6 pierce

? 理解: 布隆过滤器为什么不能删除元素？
A) 一个位被多个元素共享，清零会误伤其他元素
B) 因为哈希函数不可逆
C) 因为位数组容量太小
D) 因为它不支持并发写入
= A
+ 你元素的第 3 个哈希位，可能恰好是别人元素的第 1 个哈希位。清掉它，别人就被误判成"不存在"了。计数布隆过滤器用计数器替代单比特，才换来删除能力。

### 单链表判断是否有环，且要求额外空间 O(1)，应该用？
@ 快慢指针
A) 哈希集合记录访问过的节点
B) 快慢指针（Floyd 判圈）
C) 递归遍历并计数
D) 先反转再比较
= B
+ 快指针每次走两步、慢指针一步，有环必然相遇。哈希集合法时间也是 O(n)，但空间是 O(n)，不满足 O(1) 的要求。
% 7 5 chain

? 理解: 为什么在有环时快慢指针一定会相遇，而不是永远错开？
A) 每轮净追近一步，环上的距离必然归零
B) 因为环的长度一定是偶数
C) 因为慢指针最终会停下
D) 因为两者的哈希值相同
= A
+ 一旦两人都进环，快指针相对慢指针每轮前进 1 格。在长度为 L 的环上，距离对 L 取模后每轮加 1，必然经过 0。这就是"净追近 1"的重要性。

? 迁移: 如果让快指针每次走 3 步、慢指针 1 步，在长度为偶数的环上会怎样？
A) 可能永远不相遇，相对速度 2 只能覆盖同奇偶的节点
B) 一定相遇，而且比走 2 步更快
C) 一定不相遇
D) 与走 2 步完全等价
= A
+ 相对速度变成 2，在长度为偶数的环上只能遍历一半的节点。如果初始距离是奇数，就永远踩不到 0。经典解法要求相对速度与环长互质，2 步对 1 步恰好满足。

## 排序与查找

### 下列排序算法中，稳定的是？
@ 排序的稳定性
A) 快速排序
B) 堆排序
C) 归并排序
D) 选择排序
= C
+ 归并排序在合并时遇到相等元素优先取左边，顺序得以保持。快排的分区交换和堆排的堆调整都会打乱相等元素的相对顺序。
% 7 5 guard

? 理解: 归并排序为什么天然稳定？
A) 合并阶段遇到相等元素时优先取左侧
B) 它不做任何元素交换
C) 它使用了额外的辅助数组
D) 它的比较次数是固定的
= A
+ 稳定性不是"有没有交换"决定的，而是"相等时怎么选"决定的。归并的合并是逐个挑选，天然有"写 <= 就取左"这个自由度，取左即稳定。

? 迁移: 稳定排序最实际的用途是下面哪一个？
A) 先按次关键字排、再按主关键字排，能保留次级顺序
B) 让排序本身更快
C) 减少排序所需的内存
D) 支持浮点数比较
= A
+ 这叫多关键字排序：先按次要关键字排一遍，再稳定地按主要关键字排一遍，最终次级顺序不会被打乱。不稳定排序必须改成一次比较多个键。

### 在无序数组中找第 k 大的元素，平均 O(n) 的算法是？
@ 快速选择
A) 全排序后取下标
B) 快速选择（Quickselect）
C) 建堆后连续弹出 k 次
D) 二分查找
= B
+ 快速选择只递归处理包含目标的那一侧，平均 O(n)。全排序 O(n log n)，建堆弹 k 次是 O(n + k log n)。
% 8 6 pierce

? 理解: 快速选择的平均复杂度是 O(n) 而不是 O(n log n)，原因是？
A) 只递归含目标的那一侧，总工作量是 n + n/2 + n/4 + …
B) 因为它根本不做排序
C) 因为它用了随机数
D) 因为它只查找一次
= A
+ 快排要处理左右两边，所以每层工作量是 n，共 log n 层。快速选择只处理一边，每层工作量减半，几何级数求和收敛到 2n。

? 迁移: 快速选择的最坏时间复杂度是多少？
A) O(n²)
B) O(n log n)
C) O(n)
D) O(log n)
= A
+ 和快排一样怕不均衡划分：每轮只削掉一个元素时，工作量是 n + (n-1) + … = O(n²)。"平均 O(n)"不等于"最坏 O(n)"。

### 内存装不下的大文件排序，标准做法是？
@ 外部排序
A) 直接调 sort() 硬排
B) 外部归并排序：分块排序 + 多路归并
C) 用哈希表分组
D) 转成 JSON 再排序
= B
+ 先把文件切成能放进内存的块，每块内部排好序写回磁盘，再做多路归并。这是数据库和 MapReduce 里 shuffle 阶段的原型。
% 8 5 guard

? 理解: 多路归并里的「多路」主要是为了减少什么？
A) 归并的趟数，也就是读写磁盘的次数
B) 内存占用量
C) 元素比较次数
D) 临时文件的数量
= A
+ 二路归并对 n 条记录要跑 log2(n) 趟；改成 k 路就只要 logk(n) 趟。磁盘 IO 才是瓶颈，所以这里优化的是趟数，代价是内存里要维护 k 个堆。

### 计数排序适用的前提条件是？
@ 计数排序的门槛
A) 数据已经有序
B) 数据是范围较小的整数
C) 数据全是浮点数
D) 数据量小于 100
= B
+ 计数排序用值域大小 k 开数组统计出现次数，复杂度 O(n + k)。值域过大（比如 64 位整数）时数组开不出来，就退化了。
% 7 5 drain

? 理解: 计数排序不做两两比较，却能达到 O(n)，原因是？
A) 用值域做下标直接定位，省掉了比较
B) 它的比较被编译器优化掉了
C) 因为它只处理整数
D) 因为它内部用了哈希表
= A
+ 基于比较的排序有 O(n log n) 的下界，绕开它的唯一办法就是不做比较——直接用值本身当位置。代价是必须有界且离散的值域。

? 迁移: 0 到 10 亿范围、共 100 万个整数，计数排序还合适吗？
A) 不合适，值域太大，计数数组开不出来
B) 合适，O(n + k) 依然最快
C) 合适，把下标改成负数就行
D) 不合适，因为数据是整数
= A
+ 这里 k = 10⁹ 而 n = 10⁶，O(n + k) 完全被 k 主导，内存也撑不住。这种情况应该用基数排序，把值拆成几段，每段做一次计数排序。
