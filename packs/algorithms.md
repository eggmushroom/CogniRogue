## 复杂度

### 二分查找在 n 个有序元素上的最坏时间复杂度是？
A) O(1)
B) O(log n)
C) O(n)
D) O(n log n)
= B
+ 每次比较把搜索区间折半，最多比较约 log2(n) 次。前提是数组「有序」，无序数组先排序就已经是 O(n log n) 了。

? 理解: 为什么无序数组上不能直接用二分查找？
A) 无序数组不具备"折半后目标仍在某一侧"的性质
B) 无序数组算不出中间下标
C) 无序数组按下标访问是 O(n)
D) 无序数组元素太多，递归会爆栈
= A
+ 二分的关键不是"有序"，而是"有序"带来的可判定性：比过 mid 之后，你能确定目标只可能在左半边或右半边。无序时这个断言失效，折半就变成了瞎猜。

? 迁移: n = 1024 的有序数组，二分查找最多比较几次？
A) 10
B) 32
C) 512
D) 1024
= A
+ 2 的 10 次方是 1024，区间从 1024 缩到 1 需要 10 次折半。记住这个换算比记公式有用。

### 递归式 T(n) = 2T(n/2) + O(n) 的解是？
A) O(n)
B) O(log n)
C) O(n log n)
D) O(n²)
= C
+ 这正是归并排序的结构：分成两个 n/2 的子问题，再花 O(n) 合并。按主定理属于「平衡划分、线性合并」，结果是 O(n log n)。

? 理解: 这个递归式里的 2 和 n/2 分别对应什么？
A) 两个规模减半的子问题
B) 两次比较，每次跳过一半
C) 两层嵌套循环，每层 n/2
D) 两个长度为 n/2 的辅助数组
= A
+ 系数 2 是子问题个数，n/2 是每个子问题的规模。递归树每一层的总代价都是 O(n)，树高是 log n，乘起来才是 O(n log n)。

? 迁移: 如果合并步骤从 O(n) 变成 O(n log n)，总复杂度是多少？
A) O(n log² n)
B) O(n log n)
C) O(n²)
D) O(n√n)
= A
+ 每层代价升到 O(n log n)，层数仍是 log n，相乘即 O(n log² n)。这是"多一层对数因子"，不是平方。

### 快速排序的最坏时间复杂度出现在什么情况下？
A) 数组已经完全有序，且取首元素为枢轴
B) 数组随机排列
C) 数组元素全部相等
D) 元素数量是 2 的幂
= A
+ 已排序 + 首元素枢轴，每次划分都极不均衡（一侧空、一侧 n-1），退化成 O(n²)。三数取中或随机化枢轴就是为了打散这种最坏情况。

? 理解: 快排退化成 O(n²) 的根本原因是？
A) 每次划分极不均衡，递归树退化成一条链
B) 元素个数太多
C) 递归层数太浅
D) 每次比较的开销太大
= A
+ 快排的代价是「每层 O(n) × 层数」。均分时层数是 log n；每次只剥掉一个元素时层数是 n，于是 O(n²)。所以问题永远出在划分的均衡性上。

? 迁移: 每次都用三数取中选枢轴，能不能保证最坏 O(n log n)？
A) 不能，仍然存在被构造出来的最坏输入
B) 能，三数取中必然均分
C) 能，因为它等价于随机化枢轴
D) 不能，因为枢轴取值不唯一
= A
+ 三数取中只是降低了碰到坏输入的概率，没有消除它。要拿到最坏情况的线性保证，得用 median-of-medians 这类确定性选择算法，代价是常数极大。

### 哈希表里所有键都冲突、全部挤在同一条链上时，查找的复杂度是？
A) O(1)
B) O(log n)
C) O(n)
D) O(n log n)
= C
+ 冲突全部堆在一起时，哈希表在结构上退化成了链表，查找变成线性扫描。所以 O(1) 是平均情况，不是最坏情况。

? 理解: 为什么哈希表的 O(1) 是平均情况而不是最坏情况？
A) 冲突会让链变长，最坏时退化成线性扫描
B) 哈希函数本身的计算是 O(n)
C) 扩容时需要重新插入所有元素
D) 哈希表不支持删除操作
= A
+ 均摊 O(1) 的前提是「冲突足够均匀」。一旦哈希函数把键集中到少数桶里，桶内查找就回到了线性结构的老路。

? 迁移: 开放寻址法、装载因子已经到 0.9 时，查找性能会怎样？
A) 明显变慢，探测链变长且缓存失效
B) 不受影响，仍是 O(1)
C) 反而变快，内存更紧凑
D) 变成 O(1) 的最坏情况
= A
+ 开放寻址的成功查找期望探测次数约 1/(1-α)，α 从 0.5 涨到 0.9 时从 2 次涨到 10 次。这就是为什么实现普遍在 0.7 左右就扩容。

## 数据结构

### 同时需要「尾部插入均摊 O(1)」和「随机访问 O(1)」，应该选什么？
A) 单链表
B) 动态数组（可扩容数组）
C) 二叉搜索树
D) 哈希表
= B
+ 数组的连续内存天然支持下标随机访问；尾部追加均摊 O(1)（扩容那一次是 O(n)，摊还后可以忽略）。链表随机访问是 O(n)，哈希表不支持按下标访问。

? 理解: 为什么扩容要按倍数（比如 2 倍）而不是每次加 1？
A) 均摊之后每次追加才是 O(1)
B) 倍数扩容更省内存
C) 为了支持按下标随机访问
D) 语言运行时规定必须这样
= A
+ 每次 +1 的话，n 次追加累计复制 n²/2 个元素；每次翻倍则是 1+2+4+…+n < 2n。均摊分析里，这个"翻倍"就是 O(1) 的全部来源。

? 迁移: 从空数组开始连续 push n 次，累计复制的元素数量级是多少？
A) O(n)
B) O(n log n)
C) O(n²)
D) O(1)
= A
+ 等比数列求和上限是 2n。注意区分「单次最坏 O(n)」和「n 次总计 O(n)」——均摊就是拿这两个数相除。

### 优先队列（每次取出最小元素）最常用的底层实现是？
A) 有序数组
B) 二叉堆
C) 哈希表
D) 平衡树
= B
+ 二叉堆插入和删除堆顶都是 O(log n)，查看堆顶 O(1)，常数小、实现简单。有序数组插入是 O(n)，每次插都要挪元素。

? 理解: 二叉堆查堆顶是 O(1)，插入却是 O(log n)，原因是？
A) 堆顶固定在数组第 0 位，插入要沿树上升
B) 堆顶需要实时排序，插入直接放尾部
C) 两者其实都是 O(1)
D) 因为堆是链式结构，指针跳转慢
= A
+ 堆只保证「父子有序」这一条弱不变量，所以最小值天然在根上。插入时破坏的是从叶到根这条路径，恢复它恰好要走 log n 步。

### 并查集同时使用「路径压缩」和「按秩合并」后，单次操作的均摊复杂度约是？
A) O(1)
B) O(log n)
C) O(n)
D) O(n α(n))
= A
+ 两者结合后均摊代价是 O(α(n))，α 是阿克曼函数的反函数，在实际规模下不超过 4，因此工程上直接当作 O(1)。

? 理解: 只做路径压缩、不做按秩合并，复杂度会变成什么样？
A) 仍然很快，但理论界退化到 O(log n) 均摊
B) 直接退化到 O(n)
C) 完全不变，两种优化等价
D) 变成 O(n log n)
= A
+ 两个优化各自能拿到 O(log n)，合起来才能拿到接近常数的 α(n)。工程上两个都写几乎不增加成本，没有理由只写一半。

? 迁移: 并查集不擅长支持下面哪个操作？
A) 从一个集合中删除单个元素，并恢复它原来的归属
B) 查询两个元素是否属于同一集合
C) 合并两个集合
D) 查询某个集合的大小
= A
+ 并查集只支持「合并」，不支持「拆分」或「删除」。这是它的结构性局限，也是为什么带删除的动态连通性要用别的方法（如 LCT 或离线倒序处理）。

### 布隆过滤器判断一个元素「不存在」时，结论的正确性如何？
A) 一定正确
B) 可能误判为存在
C) 可能误判为不存在
D) 完全随机
= A
+ 布隆过滤器只有假阳性（说不存在就一定不存在）、没有假阴性。所以它适合「挡掉一定不存在」的请求，不能当作「一定存在」的证明。

? 理解: 布隆过滤器为什么不能删除元素？
A) 一个位被多个元素共享，清零会误伤其他元素
B) 因为哈希函数不可逆
C) 因为位数组容量太小
D) 因为它不支持并发写入
= A
+ 你元素的第 3 个哈希位，可能恰好是别人元素的第 1 个哈希位。清掉它，别人就被误判成"不存在"了。计数布隆过滤器用计数器替代单比特，才换来删除能力。

### 单链表判断是否有环，且要求额外空间 O(1)，应该用？
A) 哈希集合记录访问过的节点
B) 快慢指针（Floyd 判圈）
C) 递归遍历并计数
D) 先反转再比较
= B
+ 快指针每次走两步、慢指针一步，有环必然相遇。哈希集合法时间也是 O(n)，但空间是 O(n)，不满足 O(1) 的要求。

? 理解: 为什么在有环时快慢指针一定会相遇，而不是永远错开？
A) 每轮净追近一步，环上的距离必然归零
B) 因为环的长度一定是偶数
C) 因为慢指针最终会停下
D) 因为两者的哈希值相同
= A
+ 一旦两人都进环，快指针相对慢指针每轮前进 1 格。在长度为 L 的环上，距离对 L 取模后每轮加 1，必然经过 0。这就是"净追近 1"的重要性。

? 迁移: 如果让快指针每次走 3 步、慢指针 1 步，在长度为偶数的环上会怎样？
A) 可能永远不相遇，相对速度 2 只能覆盖同奇偶的节点
B) 一定相遇，而且比走 2 步更快
C) 一定不相遇
D) 与走 2 步完全等价
= A
+ 相对速度变成 2，在长度为偶数的环上只能遍历一半的节点。如果初始距离是奇数，就永远踩不到 0。经典解法要求相对速度与环长互质，2 步对 1 步恰好满足。

## 排序与查找

### 下列排序算法中，稳定的是？
A) 快速排序
B) 堆排序
C) 归并排序
D) 选择排序
= C
+ 归并排序在合并时遇到相等元素优先取左边，顺序得以保持。快排的分区交换和堆排的堆调整都会打乱相等元素的相对顺序。

? 理解: 归并排序为什么天然稳定？
A) 合并阶段遇到相等元素时优先取左侧
B) 它不做任何元素交换
C) 它使用了额外的辅助数组
D) 它的比较次数是固定的
= A
+ 稳定性不是"有没有交换"决定的，而是"相等时怎么选"决定的。归并的合并是逐个挑选，天然有"写 <= 就取左"这个自由度，取左即稳定。

? 迁移: 稳定排序最实际的用途是下面哪一个？
A) 先按次关键字排、再按主关键字排，能保留次级顺序
B) 让排序本身更快
C) 减少排序所需的内存
D) 支持浮点数比较
= A
+ 这叫多关键字排序：先按次要关键字排一遍，再稳定地按主要关键字排一遍，最终次级顺序不会被打乱。不稳定排序必须改成一次比较多个键。

### 在无序数组中找第 k 大的元素，平均 O(n) 的算法是？
A) 全排序后取下标
B) 快速选择（Quickselect）
C) 建堆后连续弹出 k 次
D) 二分查找
= B
+ 快速选择只递归处理包含目标的那一侧，平均 O(n)。全排序 O(n log n)，建堆弹 k 次是 O(n + k log n)。

? 理解: 快速选择的平均复杂度是 O(n) 而不是 O(n log n)，原因是？
A) 只递归含目标的那一侧，总工作量是 n + n/2 + n/4 + …
B) 因为它根本不做排序
C) 因为它用了随机数
D) 因为它只查找一次
= A
+ 快排要处理左右两边，所以每层工作量是 n，共 log n 层。快速选择只处理一边，每层工作量减半，几何级数求和收敛到 2n。

? 迁移: 快速选择的最坏时间复杂度是多少？
A) O(n²)
B) O(n log n)
C) O(n)
D) O(log n)
= A
+ 和快排一样怕不均衡划分：每轮只削掉一个元素时，工作量是 n + (n-1) + … = O(n²)。"平均 O(n)"不等于"最坏 O(n)"。

### 内存装不下的大文件排序，标准做法是？
A) 直接调 sort() 硬排
B) 外部归并排序：分块排序 + 多路归并
C) 用哈希表分组
D) 转成 JSON 再排序
= B
+ 先把文件切成能放进内存的块，每块内部排好序写回磁盘，再做多路归并。这是数据库和 MapReduce 里 shuffle 阶段的原型。

? 理解: 多路归并里的「多路」主要是为了减少什么？
A) 归并的趟数，也就是读写磁盘的次数
B) 内存占用量
C) 元素比较次数
D) 临时文件的数量
= A
+ 二路归并对 n 条记录要跑 log2(n) 趟；改成 k 路就只要 logk(n) 趟。磁盘 IO 才是瓶颈，所以这里优化的是趟数，代价是内存里要维护 k 个堆。

### 计数排序适用的前提条件是？
A) 数据已经有序
B) 数据是范围较小的整数
C) 数据全是浮点数
D) 数据量小于 100
= B
+ 计数排序用值域大小 k 开数组统计出现次数，复杂度 O(n + k)。值域过大（比如 64 位整数）时数组开不出来，就退化了。

? 理解: 计数排序不做两两比较，却能达到 O(n)，原因是？
A) 用值域做下标直接定位，省掉了比较
B) 它的比较被编译器优化掉了
C) 因为它只处理整数
D) 因为它内部用了哈希表
= A
+ 基于比较的排序有 O(n log n) 的下界，绕开它的唯一办法就是不做比较——直接用值本身当位置。代价是必须有界且离散的值域。

? 迁移: 0 到 10 亿范围、共 100 万个整数，计数排序还合适吗？
A) 不合适，值域太大，计数数组开不出来
B) 合适，O(n + k) 依然最快
C) 合适，把下标改成负数就行
D) 不合适，因为数据是整数
= A
+ 这里 k = 10⁹ 而 n = 10⁶，O(n + k) 完全被 k 主导，内存也撑不住。这种情况应该用基数排序，把值拆成几段，每段做一次计数排序。

## 树与堆

### 在一棵平衡的二叉搜索树里查找一个元素，时间复杂度是？
A) O(1)
B) O(log n)
C) O(n)
D) O(n log n)
= B
+ 每比较一次就下降到下一层，比较次数等于树高。平衡时树高是 log n；树退化成链时才会变成 O(n)。

? 理解: BST 的查找代价由什么决定？
A) 节点总数
B) 节点里存的值域大小
C) 树的高度
D) 插入的先后顺序
= C
+ 查找走的是一条从根到叶的路径，路径长度就是树高。节点总数 n 只是树高的上限，不是代价本身。

? 迁移: 把已经排好序的数组依次插入一棵不带自平衡的 BST，查找会变成？
A) 仍是 O(log n)
B) O(1)
C) O(n log n)
D) O(n)，树退化成一条链
= D
+ 有序插入时每个新节点都挂在最右侧，n 个节点连成一条链。这正是 AVL、红黑树这类自平衡结构要防的情况。

### 用 Floyd 自底向上法把 n 个无序元素建成二叉堆，时间复杂度是？
A) O(n log n)
B) O(n)
C) O(log n)
D) O(n²)
= B
+ 从最后一个非叶节点往前逐个下沉：底层节点多但最多下沉一层，越往上节点越少，按层加权求和收敛到 O(n)。

? 理解: 为什么逐个 insert 建堆是 O(n log n)，自底向上却只要 O(n)？
A) 自底向上不比较元素
B) 逐个插入会重复分配内存
C) 大多数节点在底层，能下沉的距离很短
D) 两者复杂度其实相同
= C
+ 一半节点是叶子，根本不需要下沉；按高度加权求和 Σ(h / 2^h) 收敛到常数乘 n。逐个插入时每个元素都可能从叶一路爬到根。

? 迁移: 建好堆后连续执行 n 次删除堆顶，总复杂度是？
A) O(n)
B) O(log n)
C) O(n²)
D) O(n log n)
= D
+ 每次删除堆顶要一次 O(log n) 的下沉，n 次就是 O(n log n)。堆排序的代价主要在这一步，不在建堆。

### AVL 树规定任意节点左右子树高度差不超过 1，主要换来的是什么？
A) 树高始终保持在 O(log n)
B) 插入不再需要比较
C) 不需要额外空间
D) 中序遍历结果变成有序数组
= A
+ 高度平衡把查找、插入、删除的最坏情况都锁在 O(log n)。代价是每次写操作可能要旋转并维护平衡因子。

? 理解: AVL 插入破坏平衡后靠什么恢复？
A) 重新插入所有节点
B) 旋转并更新平衡因子
C) 把树转成数组再重建
D) 只改根节点的键值
= B
+ 单旋处理外侧失衡、双旋处理内侧失衡，都是局部操作，只动从失衡点到根这条路径上的指针。

? 迁移: 读多写少的场景愿意选 AVL，写密集的场景常选红黑树，原因是？
A) AVL 不支持删除
B) 红黑树查找是 O(n)
C) 红黑树平衡条件更松，插入删除的旋转次数更少
D) AVL 只能存整数
= C
+ AVL 更严格地平衡，查找略快但维护更贵；红黑树用颜色换来了更少的重平衡，写操作更省。

### 数据库索引普遍用 B+ 树而不是二叉搜索树，最要紧的理由是？
A) 它不需要排序
B) 它占用的内存更小
C) 高扇出把树高压到很低，一次查询只需少数几次磁盘 IO
D) 它支持哈希查找
= C
+ 磁盘按页读写，一个节点可以塞几百个键，树高通常只有三四层。二叉树的层数多得多，每层都可能是一次 IO。

? 理解: B+ 树把实际记录放在哪里？
A) 每个节点都存一份完整记录
B) 只在根节点
C) 存在单独的哈希表里
D) 全部在叶子节点，内部节点只存键和指针
= D
+ 内部节点只做导航，因此同样一页能放更多键、扇出更高；所有查询最终都落到叶子层，路径长度一致。

? 迁移: 范围查询（取 100 到 200 之间的所有键）为什么 B+ 树比哈希索引合适？
A) 哈希索引不支持等值查询
B) 叶子节点有序且串成链表，定位起点后顺序扫描即可
C) B+ 树的键是连续整数
D) 哈希索引必须全表扫描
= B
+ 哈希把相邻的键打散到不同桶里，等值查询快但区间无能为力。B+ 树保留了顺序，这是范围扫描的前提。

### 哈夫曼编码构造出来的是一棵什么样的二叉树？
A) 带权路径长度最小的二叉树
B) 按键值有序的二叉搜索树
C) 高度最小的平衡树
D) 按字母顺序排列的字典树
= A
+ 每次贪心地合并频率最小的两棵子树，让高频字符靠近根、低频字符沉到深处，整体编码长度最小。

? 理解: 哈夫曼码为什么天然满足「任何一个编码都不是另一个编码的前缀」？
A) 编码长度都相同
B) 每个字符都用固定长度
C) 字符只放在叶子上，编码是从根到叶的路径
D) 因为只用了 0 和 1 两种符号
= C
+ 一个字符若是另一个的前缀，它就必须落在别人路径的中途，也就是内部节点上；而哈夫曼树只在叶子挂字符。

? 迁移: 出现频率越高的字符，哈夫曼编码长度通常？
A) 越长
B) 固定不变
C) 与频率无关
D) 越短
= D
+ 贪心合并时低频子树先被合并、被压得更深，高频子树留到最后、离根最近。

### 字典树（Trie）判断一个长度为 L 的字符串是否属于集合，代价主要取决于？
A) 字符串长度 L，与集合里有多少个串无关
B) 集合规模 n
C) n 与 L 的乘积
D) 字符集的大小
= A
+ Trie 把字符当边走，走 L 步就到头。哈希表平均也是 O(L)，但不支持前缀查询，还要处理冲突。

? 理解: Trie 最常被诟病的代价是什么？
A) 查询必须遍历整个集合
B) 无法判断字符串是否存在
C) 插入是 O(n²)
D) 空间开销大，每个节点要维护一组子节点指针
= D
+ 前缀共享省下的是重复部分，但指针数组本身很占空间，所以工程上常用压缩 Trie 或双数组 Trie。

? 迁移: 下面哪个场景最适合 Trie？
A) 求一个数组的中位数
B) 输入前缀时实时给出所有补全候选
C) 对数值区间求和
D) 判断图是否连通
= B
+ 补全本质上就是「找出所有以这个前缀开头的串」，Trie 上走到前缀节点再遍历子树即可。

## 图论

### Dijkstra 算法在哪种情况下会给出错误的最短路结果？
A) 图是无向图
B) 图不连通
C) 边权都是整数
D) 图中存在负权边
= D
+ 它依赖「当前距离最小的节点不可能再被松弛变短」这个贪心前提，负权边会让已经出队的节点重新变短。

? 理解: 负权边为什么破坏了 Dijkstra 的贪心前提？
A) 负权边会让优先队列为空
B) 后面绕一条负边回来，可能让已确定节点更短
C) 距离会变成负数，无法比较大小
D) 算法会陷入死循环
= B
+ 一旦允许负边，「先出队的距离就是最终距离」不再成立，而 Dijkstra 不会再回头更新已确定的节点。

? 迁移: 含负权边但无负环的单源最短路，应该改用？
A) BFS
B) Prim
C) Bellman-Ford，对所有边做 n-1 轮松弛
D) Floyd-Warshall 只跑一轮
= C
+ Bellman-Ford 不依赖贪心确定顺序；多做的第 n 轮还能顺带检测负环。

### 一个有向图能做拓扑排序，充要条件是？
A) 图中没有环（是 DAG）
B) 图是连通的
C) 每个节点入度都大于 0
D) 边权非负
= A
+ 有环意味着一组节点互为前置，谁都排不到最前面；无环图至少存在一个入度为 0 的起点。

? 理解: Kahn 算法每一轮取的是哪类节点？
A) 编号最小的节点
B) 出度最大的节点
C) 深度最大的节点
D) 当前入度为 0 的节点
= D
+ 取出后把它发出的边删掉，邻居入度减一，新的零入度节点入队 —— 这就是按依赖关系一层层剥开。

? 迁移: 同一个 DAG 的拓扑序列唯一吗？
A) 一定唯一
B) 只有当图连通时才唯一
C) 不一定，同一时刻可能有多个零入度节点，顺序任意
D) 一定不唯一
= C
+ 拓扑序只约束「边指向的后继必须排在后面」，彼此没有依赖的节点之间谁先谁后都合法。

### 边权全部相等（无权图）时求单源最短路，最直接的做法是？
A) Dijkstra 加优先队列
B) 广度优先搜索 BFS
C) Floyd-Warshall
D) 深度优先搜索 DFS
= B
+ 边数就是距离，BFS 按层扩展，第一次访问到某节点时走过的边数一定最少。

? 理解: BFS 为什么第一次访问就是最短？
A) 它遍历了所有可能路径
B) 队列保证按边数从小到大逐层扩展
C) 它每次都选权值最小的边
D) 它用了松弛操作
= B
+ 队列里节点的层数单调不减，所以先到达的一定来自更浅的层，不需要松弛也不需要优先队列。

? 迁移: 边权只有 0 和 1 时，还能保持线性复杂度吗？
A) 不能，必须上 Dijkstra
B) 不能，只能用 Bellman-Ford
C) 能，普通 BFS 就够
D) 能，用 0-1 BFS：走 0 边塞队头、走 1 边塞队尾
= D
+ 双端队列维护了「代价不降」这个性质，等价于 Dijkstra 但省掉堆，复杂度 O(V+E)。

### Kruskal 求最小生成树时，用来判断「加这条边会不会成环」的数据结构是？
A) 优先队列
B) 二叉堆
C) 并查集
D) 邻接矩阵
= C
+ 按边权升序扫描，两端已在同一集合就跳过，否则合并。并查集近似 O(1) 的 Union/Find 让整体代价主要落在排序上。

? 理解: 最小生成树为什么恰好有 n-1 条边？
A) 算法最多循环 n-1 次
B) 边权最小的只有 n-1 条
C) 连通 n 个点且无环的图就是树，边数必为 n-1
D) 并查集最多合并 n-1 次
= C
+ 生成树 = 连通 + 无环，这是树的定义；多一条边就成环，少一条就不连通。

? 迁移: 稠密图（边数接近 n²）上，哪种 MST 算法通常更省？
A) Kruskal，因为它不用排序
B) 用邻接矩阵的 Prim，O(n²)
C) 两者完全等价
D) BFS
= B
+ Kruskal 的瓶颈是 O(E log E) 排序，E 接近 n² 时反而比 O(n²) 的 Prim 更贵；稀疏图则反过来。

### 有向图的「强连通分量」指的是？
A) 分量内任意两点互相可达的极大顶点子集
B) 入度为 0 的顶点集合
C) 一个不含环的子图
D) 从源点能到达的所有顶点
= A
+ 「极大」是关键：再加任何一个外部顶点都会破坏互相可达。无向图里对应的概念就是连通分量。

? 理解: 把每个强连通分量缩成一个点之后，得到的图一定是？
A) 强连通图
B) 完全图
C) 树
D) 有向无环图 DAG
= D
+ 如果缩点后还有环，环上几个分量其实彼此可达，本该属于同一个分量，与「极大」矛盾。

? 迁移: Kosaraju 算法求 SCC 需要几次 DFS？
A) 一次
B) 三次
C) 两次：原图求完成序，再按逆序在反图上 DFS
D) 与顶点数相同
= C
+ 第一次得到完成顺序，第二次在反向图上从最晚完成的点出发，每次 DFS 恰好捞出一个分量。

### 判断「顶点 u 和 v 之间有没有一条边」，邻接矩阵相比邻接表最大的优势是？
A) 占用空间更小
B) 遍历邻居更快
C) 支持负权边
D) O(1) 直接查表
= D
+ 矩阵是二维数组，一次随机访问即可；邻接表要扫 u 的邻居链表，代价 O(deg(u))。

? 理解: 稀疏图用邻接表主要省下的是什么？
A) 判断两点相邻的时间
B) 排序时间
C) 空间：O(V+E) 而不是 O(V²)
D) 顶点的编号范围
= C
+ 边很少时矩阵里绝大多数格子都是 0，白白占着 V² 的空间。

? 迁移: 在邻接表上遍历顶点 u 的所有邻居，复杂度是？
A) O(V)
B) O(1)
C) O(V+E)
D) O(deg(u))
= D
+ 只走 u 自己那条链表；遍历全图所有顶点才是 O(V+E)。

## 递归与分治

### 递归式 T(n) = 3T(n/4) + O(n) 的渐近复杂度是？
A) O(n)
B) O(n^0.79)
C) O(n log n)
D) O(n²)
= A
+ log₄3 ≈ 0.79，而 f(n) = n 增长得更快，属于主定理第三种情况：总代价由每层的合并工作主导，结果是 Θ(n)。

? 理解: 主定理三个分支在比较什么？
A) 子问题个数与递归层数
B) 合并代价 f(n) 与 n^(log_b a) 的增长速度
C) 时间复杂度与空间复杂度
D) 最好情况与最坏情况
= B
+ n^(log_b a) 是所有叶子子问题的总量级；谁增长得更快，谁就决定总代价（第三种情况还要额外检查正则条件）。

? 迁移: T(n) = 2T(n/2) + O(1) 的结果？
A) O(log n)
B) O(n log n)
C) O(n)
D) O(1)
= C
+ 叶子子问题共有 n 个，每个花 O(1)，加起来 Θ(n)。递归求数组最大值就是这个形状。

### 标准归并排序的额外空间复杂度是？
A) O(1)
B) O(n)
C) O(log n)
D) O(n log n)
= B
+ 合并两个有序段需要一个能装下它们的辅助数组。递归栈只有 O(log n)，但辅助数组是 O(n)。

? 理解: 为什么数组上的归并排序很难做到 O(1) 额外空间？
A) 递归本身要 O(n) 空间
B) 数组不能按下标访问
C) 合并时两段的当前位置交错，必须先把一段的元素暂存
D) 比较操作需要额外内存
= C
+ 原地归并可以做，但要么大幅增加时间复杂度、要么实现极复杂，工程上通常直接用 O(n) 缓冲。

? 迁移: 把数组换成链表，归并排序的额外空间能降到？
A) 仍然是 O(n)
B) O(n log n)
C) 无法做归并排序
D) O(1)，只需改指针（不计递归栈）
= D
+ 链表节点可以摘下来重接，不需要连续缓冲；这也是链表天然适合归并、不适合快排的原因之一。

### 编译器能把递归优化成循环，通常要求递归调用满足什么条件？
A) 递归调用是函数体的最后一步，返回值不再参与后续计算
B) 递归深度小于 100
C) 函数没有参数
D) 函数返回值是整数
= A
+ 尾调用位置时当前栈帧里的局部变量已经用不上了，可以直接复用这一帧，等价于一次跳转。

? 理解: 普通递归为什么不能直接复用栈帧？
A) 它调用的层数更多
B) 子调用返回后还有没做完的运算，需要栈帧保存现场
C) 编译器不支持递归
D) 参数类型不确定
= B
+ 比如阶乘 n × fact(n-1)，乘 n 这一步要等子调用回来才能做，n 必须一直留在栈上。

? 迁移: 朴素递归求斐波那契第 n 项是 O(2^n)，最直接的优化是？
A) 改成尾递归
B) 增加递归深度上限
C) 记忆化已算过的子问题，或改成自底向上递推
D) 用更大的整数类型
= C
+ 症结是子问题大量重复；改成尾递归只是省栈，不去重仍然是指数级。

### 一个问题适合用分治，最关键的特征是？
A) 数据必须已经排好序
B) 输入规模必须是 2 的幂
C) 能拆成结构相同、彼此独立的子问题，且合并代价可控
D) 只能用递归实现
= C
+ 子问题同构才能递归求解，独立才不会重复计算，合并不能太贵否则总体复杂度会被它吃掉。

? 理解: 子问题不独立（大量重叠）时，通常改用什么策略？
A) 继续加深递归
B) 改用贪心
C) 改成回溯
D) 动态规划，把子问题的解存下来复用
= D
+ 分治与 DP 的分界线正是子问题是否重叠：重叠就记忆化，不重叠就放心分治。

? 迁移: 下面哪一类问题里「合并」这一步反而最费工夫？
A) 求数组最大值
B) 平面上最近点对，要把跨分割线的候选点再检查一遍
C) 二分查找
D) 求数组元素之和
= B
+ 左右两半各自的最近点对算完还不够，跨边界的点对可能更近；这一步没设计好，分治就退化成 O(n²)。

### 能对一个「答案值」做二分查找，隐含的前提是？
A) 可行性关于答案单调：某个值可行，比它更宽松的一侧也都可行
B) 答案一定是整数
C) 数组必须有序
D) 判定函数必须是 O(1)
= A
+ 二分的不是下标而是值域，靠的是「可行性」这条分界线；没有单调性就没法用一次判定排除一半值域。

? 理解: 二分答案和二分查找下标，最本质的区别是？
A) 二分答案不能用循环实现
B) 每次迭代要跑一次判定函数，而不是直接比较数组元素
C) 二分答案要求区间长度是偶数
D) 两者没有区别
= B
+ 下标的比较是 O(1) 的，答案的判定往往要扫一遍数据（比如「能否用 m 天搬完」），总复杂度还要乘判定代价。

? 迁移: 整数二分写 while (l < r) 且 mid 向下取整，容易卡住的原因是？
A) 整数会溢出
B) 判定函数返回了布尔值
C) 当 r = l + 1 时 mid 永远等于 l，若分支只写 l = mid，区间不再收缩
D) 答案可能是负数
= C
+ 这种写法要配合 mid 向上取整，或把区间维护成开区间，保证每一轮 l 和 r 都真的往前挪。

### 递归过深导致栈溢出，直接原因是？
A) 递归函数没有返回值
B) 时间复杂度太高
C) 每层调用都要压一个栈帧，总量超过线程栈上限
D) 变量占用了堆空间
= C
+ 栈帧里存着参数、局部变量和返回地址，空间是有限的；溢出和「跑得慢」是两件事。

? 理解: 在树上做递归遍历，最大递归深度取决于什么？
A) 节点总数
B) 叶子数
C) 节点的度数
D) 树高
= D
+ 递归沿着一条从根到叶的路径往下压栈，深度就是这条路径的长度；平衡树是 O(log n)，链状树是 O(n)。

? 迁移: 把有序数组依次插入普通 BST 后再中序遍历，会有什么风险？
A) 中序遍历结果无序
B) 树退化成链，递归深度 n，可能爆栈
C) 时间复杂度变成 O(1)
D) 没有任何风险
= B
+ 有序插入得到的是一条向右的链，中序虽然仍有序，但递归要压 n 层 —— 和自平衡树的意义正好对上。
