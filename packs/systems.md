## 操作系统

### 进程和线程最本质的区别是？
A) 进程是资源分配的单位，线程是 CPU 调度的单位；同进程内线程共享地址空间
B) 线程不能并发执行
C) 进程一定比线程轻量
D) 每个线程都拥有独立的页表
= A
+ 切换线程不必换页表、不必刷 TLB，所以更轻；但一个线程崩了可能拖垮整个进程，隔离性由进程提供。

? 理解: 同一进程里的多个线程不共享的是？
A) 栈、寄存器和程序计数器
B) 堆内存
C) 全局变量
D) 打开的文件描述符
= A
+ 共享的是地址空间和文件表，各自要有独立的调用栈与执行现场，否则函数调用会互相踩。

? 迁移: 需要强隔离（一个插件崩了不能影响主程序）时，更合适的选择是？
A) 多进程
B) 多线程
C) 协程
D) 单线程事件循环
= A
+ 隔离的代价是更贵的切换和进程间通信；用线程共享一切就换不来这层保护。

### 虚拟内存里 TLB 的作用是？
A) 缓存最近用过的页表项，避免每次访问都多级查页表
B) 存放被换出到磁盘的页面
C) 压缩物理内存
D) 记录进程优先级
= A
+ 页表本身在内存里，多级页表一次地址翻译要读好几次内存；TLB 命中时直接拿到物理页框号。

? 理解: TLB 未命中时通常会？
A) 立即触发缺页异常，把磁盘上的页读进来
B) 查页表得到映射并填入 TLB；页面可能本来就在内存里
C) 终止进程
D) 强制切换进程
= B
+ TLB miss 和 page fault 是两件事：前者只是缓存没命中，后者才是页面不在内存。

? 迁移: 遍历一个大二维数组时按行优先比按列优先快得多，主要因为？
A) 缓存局部性：连续访问命中同一条缓存行，也减少 TLB miss
B) 行优先的循环次数更少
C) 编译器只优化行优先的循环
D) 数组按行存储时元素更短
= A
+ 每一行在内存里连续，跨度大的跳跃访问会让每次取值都落到新缓存行、新页。

### 死锁的四个必要条件里，不包括哪一个？
A) 互斥使用资源
B) 占有并等待
C) 不可剥夺
D) 资源可以被无限复制
= D
+ 四个条件是互斥、占有并等待、不可剥夺、循环等待；破坏任意一条即可预防死锁。资源能无限复制就根本不会竞争。

? 理解: 「银行家算法」属于哪一类死锁处理？
A) 避免：分配前先判断系统是否仍处于安全状态
B) 预防：破坏四个必要条件之一
C) 检测与恢复
D) 忽略（鸵鸟策略）
= A
+ 它不限制进程怎么申请资源，只在每次分配前做一次安全性检查，拒绝会把系统带进不安全状态的请求。

? 迁移: 给所有资源编号、要求进程必须按编号递增顺序申请，破坏的是哪个条件？
A) 循环等待
B) 互斥
C) 不可剥夺
D) 占有并等待
= A
+ 按序申请使资源等待图里不可能出现环，也就不会有循环等待。

### 一次进程上下文切换的开销主要不包含哪一项？
A) 保存恢复寄存器、切换页表导致 TLB 失效、调度器挑下一个进程
B) 重新编译进程的代码
C) 在用户态与内核态之间切换
D) 缓存逐渐变冷带来的间接损失
= B
+ 代码不需要重新编译；真正的代价在寄存器现场、地址空间切换，以及切换后缓存命中率下降。

? 理解: 为什么线程切换通常比进程切换便宜？
A) 不需要切换地址空间，TLB 和大部分缓存仍然有效
B) 线程没有寄存器
C) 线程切换不经过内核
D) 线程不需要保存程序计数器
= A
+ 同进程内线程共享页表，省掉最贵的一项；但现场保存和调度开销仍在。

? 迁移: 高并发服务大量使用协程而不是线程，主要省下的是？
A) 内核调度与上下文切换，协程在用户态切换且栈更小
B) 网络带宽
C) 磁盘 IO 次数
D) 页表大小
= A
+ 协程把调度搬到用户态，切换只需换几个寄存器；代价是一个协程阻塞住就可能卡住整个线程。

### LRU 页面置换算法的依据是？
A) 最近一段时间没被访问的页，短期内大概率也不会被访问
B) 页面越小越应该先换出
C) 最早进入内存的页一定不再使用
D) 换出脏页比换出干净页便宜
= A
+ 它用时间局部性做预测；FIFO 只看进入顺序，可能把最常访问的页换出去。

? 理解: 增加物理页框数反而让缺页次数上升，这种现象叫？
A) Belady 异常，FIFO 等不满足栈性质的算法会出现
B) 系统抖动
C) 内存碎片
D) 页面颠簸
= A
+ LRU 属于栈算法，页框越多命中集合只会更大，不会出现这种反常；FIFO 会。

? 迁移: 换出一个「脏页」比换出干净页多出的代价是？
A) 必须先把内容写回磁盘
B) 要修改页表大小
C) 需要重新分配 TLB
D) 要通知所有进程
= A
+ 干净页在磁盘上有相同副本，直接覆盖即可；脏页被改过，回收前必须先 flush。

### 用户程序发起系统调用时，控制权进入内核靠的是？
A) 一条受控的陷入指令（trap / syscall），切到特权态并跳转到固定入口
B) 一次普通的函数调用
C) 直接跳转到内核里的任意地址
D) 重新加载整个操作系统
= A
+ 入口和参数都要经过内核校验，用户态不能自己指定内核代码地址，这是特权级隔离的关键。

? 理解: 为什么 read() 比一次普通的内存读取慢得多？
A) 要跨越特权级、做参数检查、可能阻塞等设备和触发缺页
B) 因为磁盘一定是随机读写
C) 因为 C 库函数有额外包装
D) 因为文件描述符是整数
= A
+ 普通访存是一条指令；系统调用是「陷入 + 校验 + 调度 + 设备」整条路径，且可能把进程挂起。

? 迁移: 频繁的小块读写改成缓冲区批量读写，主要省掉的是？
A) 系统调用次数以及每次陷入的固定开销
B) 磁盘读写的总字节数
C) 进程占用的内存
D) 文件描述符数量
= A
+ 数据量没变，变的是跨越用户/内核边界的次数；标准库的缓冲就是这个思路。

## 计算机网络

### TCP 建立连接为什么是三次握手而不是两次？
A) 三次比两次更快
B) 让双方都确认「自己的发送和对方的接收」正常，并防止已失效的旧连接请求突然到达
C) 协议规定必须是奇数次
D) 为了协商端口号
= B
+ 两次时服务端无法确认客户端是否收到了自己的 SYN-ACK；旧的重复 SYN 也会让服务端白白建起一条连接。

? 理解: 第三次握手（客户端的 ACK）丢失会怎样？
A) 服务端重传 SYN-ACK，客户端已认为自己进入已连接状态
B) 双方会一直等待，连接永远建不起来
C) 连接立刻降级成 UDP
D) 客户端必须重新发 SYN
= A
+ 客户端发完 ACK 就进入 ESTABLISHED；服务端没收到会超时重传，收到客户端重发的 ACK 后补上。

? 迁移: 四次挥手里 TIME_WAIT 留在主动关闭方，主要作用是？
A) 保证最后一个 ACK 能送达，并让本次连接的迟到报文在网络中消散
B) 等待对方释放端口
C) 减少网络拥塞
D) 重传所有数据
= A
+ 若最后的 ACK 丢了，对方会重发 FIN，需要有人能回 ACK；同时避免旧连接的迟到包污染新连接。

### 下面哪一项是 TCP 提供而 UDP 不提供的？
A) 按序、可靠、不重复的字节流交付
B) 源端口与目的端口
C) 校验和
D) 数据包的边界
= A
+ UDP 只加了端口和可选校验和，不保证送达、不保证顺序、也不重传；可靠有序是 TCP 用序号、确认和重传堆出来的。

? 理解: TCP 是「字节流」而不是「报文」协议，这意味着？
A) 发送方 write 三次，接收方可能一次 read 就读完，应用层要自己处理粘包
B) 每条消息都有固定边界
C) 只能传输文本
D) 不能并发发送
= A
+ TCP 不保留应用层写入的边界；要区分消息得自己加长度字段或分隔符。

? 迁移: 实时音视频更愿意用 UDP，主要因为？
A) 迟到重传的数据对播放已经没用，宁可丢包也不愿等
B) UDP 的带宽更大
C) UDP 更安全
D) UDP 不需要端口号
= A
+ 可靠性是用延迟换来的；实时场景里「按时到」比「必须到」重要，重传反而造成卡顿累积。

### TCP 慢启动阶段，拥塞窗口 cwnd 随往返时间大致怎么增长？
A) 每收到一个 ACK 加一个 MSS，一个 RTT 内近似翻倍
B) 每个 RTT 固定加 1 个 MSS
C) 保持不变
D) 按线性函数缓慢增长
= A
+ 指数增长让它快速探到可用带宽；到达 ssthresh 后切进拥塞避免，改为每 RTT 加约 1 个 MSS 的线性增长。

? 理解: 收到三个重复 ACK 触发快速重传时，通常怎么处理 cwnd？
A) 直接把 cwnd 重置为 1
B) 快速恢复：把 ssthresh 减半后适当收缩 cwnd，不必退回慢启动
C) 关闭连接
D) 把 cwnd 翻倍
= B
+ 三个重复 ACK 说明后续报文还在到达，网络只是丢了包没堵死，因此不必像超时那样从零重来。

? 迁移: 重传超时（RTO）为什么比三个重复 ACK 处理得保守得多？
A) 超时意味着连后续 ACK 都没回来，无法判断网络是否还通，只能退回慢启动
B) 超时的包一定更大
C) 超时会重置端口号
D) 两者处理完全相同
= A
+ 重复 ACK 是「网络还在送货」的证据，超时没有任何证据，所以采取最保守的探测。

### TCP 首部里的「接收窗口」字段主要用来解决？
A) 发送方别发得比接收方处理得快（端到端的流量控制）
B) 链路中间的路由器别被塞满（拥塞控制）
C) 数据加密
D) 路由选择
= A
+ rwnd 由接收方通告，随应用读取数据的速度变化；它保护接收端缓冲区，而拥塞窗口 cwnd 保护的是网络。

? 理解: 发送方实际可用的发送窗口取什么值？
A) min(接收窗口 rwnd, 拥塞窗口 cwnd)
B) rwnd + cwnd
C) max(rwnd, cwnd)
D) 只取 cwnd
= A
+ 两个限制必须同时满足：再宽的网络带宽也不能灌满接收方缓冲区，反之亦然。

? 迁移: 接收方应用层一直不 read，会出现什么现象？
A) 接收缓冲区填满、通告窗口缩到 0，发送方停止发送并定期做零窗口探测
B) 数据被自动丢弃且不重传
C) 连接立刻断开
D) 发送方自动改用 UDP
= A
+ 这就是「零窗口」；发送方要靠 persist 定时器定期探测窗口是否已重新打开。

### 浏览器输入域名到拿到 IP，DNS 递归查询的大致顺序是？
A) 权威服务器 → 根 → 本地缓存
B) 本地缓存 → 递归解析器 → 根 → 顶级域 → 权威服务器
C) 顶级域 → 本地缓存 → 根
D) 直接问目标主机
= B
+ 递归解析器替客户端逐级问下去：根告诉它该找哪个 TLD，TLD 告诉它该找哪台权威，权威给出最终记录。

? 理解: DNS 缓存记录里的 TTL 作用是？
A) 规定这条解析结果能被缓存多久，过期后必须重新查询
B) 限制查询包的大小
C) 决定用 TCP 还是 UDP
D) 表示网络跳数上限
= A
+ TTL 是「变更生效速度」与「查询压力」之间的权衡；改解析记录前先调小 TTL 就是这个原因。

? 迁移: DNS 主要使用 UDP 而不是 TCP，原因是？
A) 一问一答、报文很小，省掉握手开销；响应过长或区域传送时才换 TCP
B) UDP 更可靠
C) TCP 不支持 53 端口
D) UDP 自带拥塞控制
= A
+ 短事务用 UDP 最省；报文过大、以及主从服务器之间的区域传送会改走 TCP。

## 数据库

### 事务 ACID 里的 I（隔离性）指的是？
A) 并发执行的事务互不看到对方未完成的中间状态
B) 事务一旦提交，结果就永久保存
C) 事务要么全做要么全不做
D) 事务执行前后数据库都满足约束
= A
+ A 是原子性、C 是一致性、D 是持久性；隔离性由锁或 MVCC 配合隔离级别实现，级别越低并发越高、异常越多。

? 理解: 「转账扣了钱但没加钱」违反了哪一条？
A) 原子性
B) 隔离性
C) 持久性
D) 一致性约束之外的独立特性
= A
+ 事务必须作为一个不可分割的整体回滚；崩溃恢复靠日志把未提交的修改撤掉。

? 迁移: 已提交事务的结果在断电后仍不丢，通常靠什么保证？
A) 预写日志 WAL：先把日志落盘再改数据页
B) 更大的内存缓冲池
C) 更快的 CPU
D) 定期重启服务
= A
+ 日志顺序追加并 fsync 之后才返回提交成功；崩溃后按日志重做已提交、回滚未提交。

### 「不可重复读」指的是哪种现象？
A) 同一事务里两次读同一行，结果不同（中间被别的事务改了并提交）
B) 读到了别的事务还没提交的修改
C) 同一条件两次查询，行数变多了
D) 两个事务互相等待对方释放锁
= A
+ 读到未提交是脏读；同条件范围查询多出行是幻读；不可重复读针对的是已存在行的更新。

? 理解: 可重复读（repeatable read）主要消除的是？
A) 只消除脏读
B) 脏读与不可重复读；是否消除幻读取决于实现
C) 所有并发异常
D) 死锁
= B
+ SQL 标准里 RR 仍允许幻读，但 InnoDB 的 MVCC 加 next-key lock 在这个级别就挡住了大部分幻读。

? 迁移: 串行化（serializable）代价最高的原因是？
A) 它不能并发读
B) 要让并发事务的结果等价于某种串行执行顺序，通常靠更重的加锁或冲突检测
C) 它禁止使用索引
D) 它必须关闭日志
= B
+ 隔离越严格，能并行的操作越少；吞吐与一致性之间的取舍就是选隔离级别。

### 联合索引 (a, b, c) 上，下面哪个查询条件无法充分利用最左前缀？
A) WHERE b = 1 AND c = 2（不带 a）
B) WHERE a = 1
C) WHERE a = 1 AND b = 2
D) WHERE a = 1 AND b = 2 AND c = 3
= A
+ B+ 树按 (a, b, c) 的字典序排，跳过最左列后整体不再有序，只能退化为扫描或松散索引扫描。

? 理解: WHERE a > 1 AND b = 2 里，b 为什么通常不能继续走索引？
A) b 的类型不匹配
B) a 是范围条件后，后面的 b 在索引里不再是有序的一段
C) 优化器不支持两个条件
D) 范围条件必须写在最后
= B
+ 范围把 a 切成许多不连续的值，每个 a 值内部 b 才有序，合起来没有全局顺序，因此索引到 a 就停了。

? 迁移: 「覆盖索引」指的是？
A) 查询需要的列全在索引里，不必回表读数据行
B) 索引包含了表的所有列
C) 索引一定建在主键上
D) 一个查询同时用了多个索引
= A
+ 二级索引叶子存主键值，若还要取别的列就得回表；把常查的列一起放进联合索引可以省掉这一步。

### 第三范式（3NF）主要消除的是？
A) 非主属性对码的部分函数依赖
B) 非主属性对码的传递函数依赖
C) 多值依赖
D) 完全重复的行
= B
+ 1NF 要求属性原子、2NF 消除部分依赖（针对联合主键）、3NF 消除传递依赖；BCNF 进一步把决定因素限制为候选码。

? 理解: 在订单表里重复存客户姓名和地址，最主要的坏处是？
A) 更新异常：改一次客户信息要改很多行，漏改就产生不一致
B) 查询一定变慢
C) 表上不能建索引
D) 无法做备份
= A
+ 冗余本身不一定错，但要付出「写入时保持一致」的代价；反范式就是用这个代价换查询性能。

? 迁移: 读多写少的报表场景故意保留冗余字段，这种做法叫？
A) 反范式化
B) 进一步规范化
C) 分片
D) 索引覆盖
= A
+ 它是有意识的取舍：省掉 JOIN，把一致性责任挪到写入侧或离线同步任务里。

### MVCC 让读不阻塞写、写不阻塞读，靠的是？
A) 给整张表加共享锁
B) 把所有写操作排队串行执行
C) 保留数据的多个版本，读事务按自己的快照去读对应版本
D) 关闭事务日志
= C
+ 每行带版本号或事务 ID，读事务根据可见性规则挑选版本；一致性读因此不需要加锁。

? 理解: 可重复读级别下，快照读两次查询看到的结果为什么一致？
A) 事务开始时确定一次读视图，整个事务都按它判断版本可见性
B) 数据库把第一次的查询结果缓存起来了
C) 表被锁住了
D) 写事务被挂起了
= A
+ 读视图固定后，后提交的版本对本事务不可见；这是「可重复读」的实现方式，不是缓存命中。

? 迁移: MVCC 的主要代价是？
A) 读操作必须加锁
B) 无法支持并发写
C) 旧版本占额外存储，需要后台清理不再被任何事务看到的版本
D) 事务不能回滚
= C
+ 版本链和 undo 日志都要空间；长事务迟迟不结束会拖住清理，这是线上常见的空间膨胀来源。

## 并发与同步

### 两个线程同时执行 count++ 却得到小于预期的值，根本原因是？
A) CPU 不支持加法指令
B) 变量被分配在堆上
C) 「读—改—写」不是原子操作，两个线程可能基于同一个旧值各写一次
D) 编译器把循环优化掉了
= C
+ count++ 至少拆成取数、加一、写回三步；交错执行会丢失一次更新，结果依赖时序，这就是竞态。

? 理解: 把变量声明为 volatile（Java/C# 语义）能解决 count++ 吗？
A) 能，volatile 等价于互斥锁
B) 不能，它只保证可见性和禁止部分重排，不保证复合操作原子
C) 能，但只在单核机器上
D) 不能，因为它会让变量变成只读
= B
+ 可见性解决「读不到别人刚写的值」，原子性解决「两步之间不被插队」，是两个不同的问题。

? 迁移: 不用锁又要保证 count++ 正确，最合适的原语是？
A) CAS（比较并交换）或原子自增，冲突时重试
B) 把变量声明为 volatile
C) 增大缓冲区
D) 把变量改成浮点类型
= A
+ CAS 把「读旧值 + 写新值」合成一条硬件原子指令，失败就循环重试，是无锁编程的基本构件。

### 自旋锁更适合哪种场景？
A) 临界区里要做磁盘 IO
B) 临界区极短、锁很快就能释放，且不愿付出上下文切换代价
C) 单核单线程环境
D) 持锁时间完全不可预测
= B
+ 忙等会白烧 CPU，只有当「等的时间短于一次上下文切换」才划算；临界区里阻塞或睡眠更是绝不能自旋。

? 理解: 持有自旋锁的线程被抢占，会发生什么？
A) 锁自动升级成互斥锁
B) 其他等待者一直空转，直到它被重新调度并释放锁，CPU 被大量浪费
C) 系统立刻死锁
D) 等待线程自动进入睡眠
= B
+ 这正是内核里自旋锁通常要配合禁止抢占一起使用的原因。

? 迁移: 读多写少的场景用读写锁，主要收益是？
A) 写操作也无需等待
B) 多个读可以并行，只在写时独占
C) 完全避免死锁
D) 省掉内存屏障
= B
+ 读之间不冲突，把它们从互斥里放开；代价是写可能饿死，因此实现上常有写优先策略。

### 编译器和 CPU 都会重排指令，内存屏障的作用是？
A) 提高缓存命中率
B) 约束屏障两侧的访存顺序，让其他核按约定的顺序观察到写入
C) 阻止所有中断
D) 把变量常驻寄存器
= B
+ 单核上看不见的重排，在多核共享内存下会变成「标志位先可见、数据后可见」这类诡异 bug；屏障给出顺序保证。

? 理解: 无锁队列里先写数据、再「发布」标志位，发布侧通常需要？
A) 读屏障（acquire）
B) 写屏障（release），保证数据写入先于标志位对其他核可见
C) 不需要任何屏障
D) 全局互斥锁
= B
+ 消费侧配 acquire 读，两侧成对才构成 happens-before；只加一侧仍可能读到旧数据。

? 迁移: happens-before 关系保证的是？
A) 两个操作在同一时刻发生
B) 前一个操作的结果对后一个操作可见，且不会被重排到它之后
C) 代码执行速度更快
D) 线程不会被切换
= B
+ 它是内存模型给程序员的顺序契约，不是物理时间上的先后。

### CAS 的 ABA 问题指的是？
A) 值从 A 被改成 B 又改回 A，CAS 只看值相同就认为没变过
B) 比较和交换之间被中断
C) 两个线程同时成功
D) 变量发生溢出
= A
+ 指针复用、对象池回收这类场景里，「值没变」不等于「状态没变」，可能读到已经失效的中间状态。

? 理解: 解决 ABA 的常见手段是？
A) 给值附加单调递增的版本号，比较时连版本一起比
B) 把 CAS 换成普通赋值
C) 降低重试次数
D) 单纯增大变量位宽
= A
+ 双字 CAS 比较「值 + 版本」，即使值回到 A，版本也已经不同了。

? 迁移: CAS 循环在高竞争下最容易出现的问题是？
A) 大量线程反复失败重试，CPU 空转，吞吐反而低于加锁
B) 内存泄漏
C) 死锁
D) 数据一定不一致
= A
+ 无锁不等于更快；竞争激烈时退避、分片计数或直接上锁往往更实际。

### 计数信号量 sem 的当前值是 3，含义是？
A) 已经有 3 个线程在等待
B) 最多还能做 3 次 P 操作
C) 还有 3 个资源可用，最多允许 3 个线程同时进入受保护区域
D) 等待队列长度是 3
= C
+ P（wait）把计数减一，减到负数就阻塞；V（signal）加一并唤醒等待者，用来控制同时访问的线程数量。

? 理解: 初值为 1 的二值信号量，作用最接近？
A) 互斥锁
B) 读写锁
C) 条件变量
D) 线程屏障
= A
+ 只允许一个线程进入；但它与互斥锁的语义差别在于信号量可以由别的线程 V，互斥锁要求谁加锁谁解锁。

? 迁移: 生产者—消费者只用一个信号量为什么不够？
A) 缓冲区必须无限大
B) 还需要一个表示空槽数的信号量，以及对缓冲区本身的互斥访问
C) 消费者必须改成轮询
D) 必须再加一个自旋锁
= B
+ 「有数据可取」和「有空位可放」是两个不同条件，再配上缓冲区的互斥，才算完整。

## 体系结构与编译

### 程序的时间局部性和空间局部性分别指？
A) 刚访问过的数据很可能再被访问；访问某位置时，附近位置也很快被访问
B) 程序只在白天运行；数据放在同一台机器上
C) 指令比数据更常被访问；数组比链表更快
D) 缓存比内存快；内存比磁盘快
= A
+ 整个缓存体系就是为这两条统计规律建的：循环里反复用同一变量是时间局部性，顺序扫数组是空间局部性。

? 理解: 缓存行通常是 64 字节，意味着？
A) 每次只能读 64 个 bit
B) 读一个 int 会把相邻的一整块一起搬进缓存
C) 缓存总容量固定为 64 字节
D) 内存按 64 字节分页
= B
+ 这也是「结构体数组 vs 数组结构体」以及伪共享问题的来源：相邻数据被绑在同一行里。

? 迁移: 多线程各写一个独立计数器却很慢，可能是？
A) 几个计数器落在同一缓存行，相互失效造成伪共享
B) 变量类型太小
C) 线程数超过了核数
D) 编译器没开优化
= A
+ 数据逻辑上独立、物理上共享一行，写一次就让别的核的副本失效；按缓存行对齐或填充可解决。

### CPU 流水线里的「数据冒险」指的是？
A) 两条指令同时要占用同一个功能部件
B) 后一条指令要用到前一条还没写回的结果
C) 分支指令还没决定跳转方向
D) 指令长度不一致
= B
+ 结构冒险抢硬件资源、控制冒险来自分支、数据冒险来自真相关；旁路（forwarding）能消掉大部分停顿。

? 理解: 分支预测主要缓解的是哪种冒险？
A) 控制冒险
B) 数据冒险
C) 结构冒险
D) 输出相关
= A
+ 不等分支结果就先按预测方向取指执行；猜错要清空流水线，代价是若干周期的惩罚。

? 迁移: 编译器做循环展开，除了减少分支次数还带来什么？
A) 一定能减少缓存 miss
B) 更多可并行的独立指令，方便填满流水线；代价是代码体积变大
C) 降低寄存器压力
D) 消除所有数据依赖
= B
+ 展开让多个迭代的运算同时在流水线里飞，但会吃掉更多寄存器、让指令缓存压力上升。

### 编译器前端里，把字符流变成 token 的是哪个阶段？
A) 词法分析
B) 语法分析
C) 语义分析
D) 代码生成
= A
+ 词法分析产出 token 序列，语法分析按文法组成 AST，语义分析查类型和作用域，之后才到中间代码与目标代码。

? 理解: 语法分析的输入和输出分别是？
A) 源代码字符 → token 序列
B) token 序列 → 抽象语法树
C) 抽象语法树 → 汇编代码
D) 汇编代码 → 机器码
= B
+ 它检查的是「结构是否符合文法」，还不管变量有没有声明 —— 那属于语义分析。

? 迁移: 「使用了未定义的变量」这类错误通常在哪个阶段被抓到？
A) 语义分析（查符号表与类型检查）
B) 词法分析
C) 语法分析
D) 链接
= A
+ 语法上 a + 1 完全合法，只有查符号表才知道 a 有没有声明、类型是否匹配。

### 0.1 + 0.2 在多数语言里不等于 0.3，根本原因是？
A) CPU 不支持小数加法
B) 0.1 和 0.2 在二进制里是无限循环小数，IEEE 754 只能存有限位近似值
C) 编译器算错了
D) double 的指数位是负数
= B
+ 十进制的有限小数未必能写成二进制有限小数；误差在存储那一步就产生了，不是运算造出来的。

? 理解: 比较两个浮点数是否相等，更稳妥的做法是？
A) 先转成字符串再比较
B) 判断差的绝对值是否小于容差（相对误差更严谨）
C) 直接用 ==
D) 先取整再比较
= B
+ 容差要和量级匹配；金额这类需要精确十进制的场景应改用定点数或十进制类型。

? 迁移: float 能表示的整数超过约 2^24 后开始不连续，原因是？
A) 指数位用完了
B) 符号位被占用
C) 尾数只有 24 位有效精度，再大只能按 2 的幂跳着表示
D) 内存不够
= C
+ 精度由尾数位数决定，范围由指数决定；这也是大整数时间戳不该用单精度浮点存的原因。

### Amdahl 定律说明并行加速比的上限取决于？
A) 程序里无法并行的串行部分占比
B) CPU 的核数
C) 内存带宽
D) 编译器版本
= A
+ 哪怕把可并行部分降到零耗时，总时间也至少是原来串行部分那么长；加速比上限是 1 / 串行占比。

? 理解: 一个程序有 20% 的时间必须串行执行，即便用无限多核，最大加速比约为？
A) 5 倍
B) 10 倍
C) 20 倍
D) 无限
= A
+ 1 / 0.2 = 5；把剩下 80% 全部并行到零耗时，也只是把总时间从 1 压到 0.2。

? 迁移: Gustafson 定律与 Amdahl 的视角差别是？
A) 它认为串行部分不存在
B) 它假设问题规模随核数一起放大，串行部分占比因此下降
C) 它只适用于 GPU
D) 两者完全相同
= B
+ 强扩展（固定问题规模）容易撞上串行上限；弱扩展（规模随资源增长）能继续吃到并行收益。
